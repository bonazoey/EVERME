## EVERME 프론트엔드 스타일 컨벤션

이하 기준은 사용자가 확정한 UI 요구와 현재 화면에 따른다. 이후 사용자의 명시적인 요청이 우선한다. 기능과 무관한 디자인 변경이나 라이브러리 도입은 하지 않는다.

### 디자인 방향과 색상

- 밝은 테마를 기본으로 한다. 콘텐츠 영역은 흰색, 사이드바 배경은 포인트 녹색, 사이드바의 기본 글자·아이콘·구분선은 연한 파스텔 녹색을 사용한다. 시스템 테마에 따른 다크 모드는 추가하지 않는다.
- 공통 색상은 globals.css의 변수를 재사용한다.
- 목업의 녹색 테마와 레이아웃은 유지하되 작은 글자·placeholder·버튼 글자는 배경과 4.5:1 이상 대비를 목표로 한다. 사이드바 날짜 구분 문구는 text-green-light/95로 표시하며, 낮은 투명도로 흐리게 만들지 않는다.

| 용도                 | 값                     |
| -------------------- | ---------------------- |
| 포인트               | --green: #4C7059       |
| 선택·호버 배경       | --green-light: #EAF7EF |
| 본문                 | --ink: #17212B         |
| 보조 문구·기본 메뉴  | --muted: #526D5B       |
| 기본 테두리          | --line: #E0E7E4        |
| 보조 표면            | --surface: #F7F9F8     |
| 사이드바 배경        | var(--green)           |
| 사이드바 글자·구분선 | var(--green-light)     |

- 사이드바 안의 테두리·구분선·계정 팝업 테두리는 로컬 --line: var(--green-light)를 사용한다.
- 사이드바의 선택된 상위 메뉴는 포인트 색상에 검정 12%를 섞은 배경(color-mix(in srgb, var(--green) 88%, black))과 연녹색 세로 막대·굵은 글씨로 표시한다. 하위 항목은 배경색을 바꾸지 않는다. 계정 버튼도 호버·팝업 열린 상태에서 같은 어두운 배경을 사용하며 글자색은 연녹색으로 유지한다. 모드 전환 버튼은 호버 시 연녹색 배경과 녹색 글자를 사용한다.
- 기본 글꼴은 Arial, "Malgun Gothic", "Apple SD Gothic Neo", sans-serif, 본문 크기는 15px, 줄 높이는 1.6이다.

### 파일·컴포넌트·스타일 구성

- Next.js App Router를 사용한다. 독립된 화면은 경로 폴더의 page.js로 정의한다.
- 페이지는 폴더형, UI 컴포넌트는 단일 JS 파일형으로 만든다. 여러 화면에서 공유하는 UI만 src/components에 두고, 화면 전용 컴포넌트는 사용하는 페이지 근처에 둔다.
- 인증 화면은 app/(auth), 서비스 화면은 app/(service)의 layout.js에서 공통 틀을 적용한다. 괄호 그룹명은 URL에 포함하지 않는다.
- (auth)와 (service)는 기능 영역과 레이아웃을 구분하는 라우트 그룹이다. 호스트·서브도메인을 분리하거나 인증 접근 제어를 자동으로 적용하는 설정은 아니다.
- 인증 UI는 각 페이지에 직접 작성한다. 회원가입의 동의 단계와 비밀번호 재설정의 발송 안내는 해당 페이지의 로컬 상태로 관리한다. 메일 링크로 직접 진입하는 새 비밀번호 설정은 독립 경로를 유지한다. AuthForm의 screen 분기로 독립 화면들을 한 컴포넌트에 모으지 않는다.
- 모달·드롭다운·로딩·토스트·탭·음성 전환 같은 화면 내부 상태는 사용하는 페이지의 로컬 상태로 관리한다. 이를 위해 별도 page.js나 라우트를 만들지 않는다.
- 페이지 전용 모달 내용은 해당 페이지에 직접 포함하고 공통 Modal 틀만 재사용한다. 단일 페이지를 감싸기만 하는 Content 컴포넌트는 만들지 않는다. 사용자·정보이용자 화면에서 실제로 공유하는 채팅·설정 UI는 공유 컴포넌트로 유지한다.
- 모달 열기·닫기·저장·취소는 onClick/onClose로 처리한다. 실제 화면 이동과 대화 식별에만 URL을 사용한다. 모달은 Escape·배경 클릭으로 닫고 포커스를 모달 안에 유지한 뒤 닫을 때 원래 위치로 복원한다.
- 화면과 공유 UI 스타일은 JSX의 Tailwind CSS 유틸리티로 작성한다. 새 .module.css 파일이나 CSS Modules 클래스 매핑 헬퍼를 추가하지 않는다.
- 레이아웃·간격·글꼴·상태는 기본 유틸리티를 우선한다. 정확한 값이나 복합 선택자가 필요할 때만 임의 값과 `[&...]:` 변형을 사용한다.
- 색상은 globals.css의 CSS 변수와 `@theme inline` 토큰을 재사용한다. 예: `text-green`, `text-muted`, `bg-green-light`, `border-line`.
- globals.css에는 Tailwind import, 테마 토큰, `@layer base` 안의 초기화·기본 태그 스타일만 둔다. 화면별 스타일과 반응형 규칙은 JSX에서 정의한다. 기본 스타일은 유틸리티로 덮어쓸 수 있어야 한다.
- 반복되는 UI는 src/components의 공용 컴포넌트로 재사용한다. 변형은 완전한 클래스 문자열을 가진 정적 매핑이나 조건식으로 정의한다. `bg-${color}`처럼 Tailwind가 탐지할 수 없는 클래스 조합은 만들지 않는다.
- 기존 최대 1100px·760px, 최소 1600px 경계와 모바일 탐색 동작을 유지한다. 포함 경계가 필요한 경우 `[@media(max-width:_760px)]:` 같은 미디어 변형을 사용한다. 기본 sm·md 경계로 임의 변경하지 않는다.
- 호버·포커스·체크 상태는 Tailwind 변형으로 표현한다. 터치 환경과 키보드 접근성을 유지한다.
- `ui-*` 클래스는 복합 상태와 부모·자식 선택자를 연결하는 스타일 없는 훅이다. 스타일은 함께 있는 Tailwind 유틸리티가 담당한다. 일반 요소에 불필요한 훅을 추가하지 않는다.
- 부모에서 공용 UI 배치를 조정할 때는 `[&_.ui-button]:...`처럼 범위를 제한한다. 광범위 전역 선택자나 불필요한 !important는 추가하지 않는다.
- Tailwind Turbopack 로더는 globals.css에만 적용한다. 런타임 값(예: 음성 파형 높이)만 인라인 style을 허용한다.

### 사이드바

- 브랜드는 공용 EvermeMascot 컴포넌트를 텍스트 EVERME 왼쪽에 배치한다. 마스코트 36×36px, 간격 10px, 세로 중앙 정렬을 유지한다. 사이드바는 animated={false}로 정적인 마스코트를 사용하고 채팅에서만 랜덤 표정 모션을 적용한다. EVERME 글자는 Trebuchet MS, Verdana, sans-serif 순서의 글꼴, font-weight: 600, 자간 1.5px을 사용한다.
- 데스크톱 사이드바의 현재 너비는 300px이다. 너비를 변경할 때는 서비스 콘텐츠의 좌측 여백도 함께 확인해 겹치지 않게 한다.
- 모드 버튼은 현재 모드를 표시하고 클릭하면 반대 모드로 바로 이동한다. 드롭다운으로 바꾸지 않는다.
- 모드 버튼은 다른 메뉴와 같은 기본 글자 크기·var(--green-light) 색상을 사용하되, 항상 font-weight: 700으로 표시한다.
- 최근 대화 목록은 AI 대화 버튼을 클릭할 때만 펼치거나 접는다. 다른 상위 메뉴·로고·모드 전환·계정 메뉴를 클릭하거나 새 대화를 생성해도 펼침 상태를 변경하지 않는다. AI 클론은 /owner/clone 대시보드로 바로 이동하는 링크이며 하위 항목을 두지 않는다.
- AI 대화 오른쪽에 원형 + 버튼을 둔다. 연녹색 테두리를 적용하고, 호버 배경은 상위 메뉴 선택 배경과 같은 color-mix(in srgb, var(--green) 88%, black)을 사용한다. 클릭하면 빈 새 대화를 연다.
- 최근 대화는 최대 5개 행 높이까지 표시하고 초과 항목은 세로 스크롤로 확인한다. 항목의 ··· 메뉴는 hover 또는 키보드 포커스 시 표시하며, 터치 환경에서도 접근 가능해야 한다.
- 최근 대화 목록은 왼쪽 24px 들여쓰기를 적용한다. 제목 앞의 고정 너비 영역에는 기본 중간점, 선택 시 연녹색 세로 막대(3×16px)를 표시한다. 표시는 aria-hidden으로 두고 선택 링크에는 aria-current를 적용한다. 제목과의 간격은 8px이며 긴 제목만 말줄임 처리한다.
- 최근 대화의 ··· 메뉴는 버튼 오른쪽 아래에 표시한다. Portal과 fixed 배치로 히스토리 스크롤 영역에서 분리해 스크롤 높이·너비에 영향을 주지 않게 한다. 바깥 클릭·Escape로 닫고, 스크롤·화면 크기 변경 시 닫아 위치가 어긋나지 않게 한다.
- 접근 이력은 /owner/clone 대시보드의 주요 특징 아래에 함께 표시한다.
- 상위 메뉴는 선택 시 살짝 어두운 녹색 배경, 왼쪽 연녹색 세로 막대(너비 5px·선택 배경과 같은 전체 높이), font-weight: 700으로 구분한다. 하위 메뉴는 배경색 없이 중간점을 세로 막대로 바꾸고 글씨를 굵게 표시한다. 기본 메뉴 높이 48px, 모서리 8px, 하위 항목 높이 32px·글자 크기 13px·가로 패딩 5px를 기준으로 한다. 최근 대화 목록의 최대 높이는 5행에 맞춰 160px로 둔다.
- 계정 설정을 주 메뉴에 넣지 않는다. 하단 이름·이메일 영역을 누르면 위쪽으로 계정 팝업을 열고 계정 설정·로그아웃을 제공한다.
- 계정 팝업은 바깥 클릭과 Escape로 닫을 수 있어야 한다.
- 계정 팝업은 연녹색 배경과 녹색 글자·아이콘으로 반전해 표시한다. 팝업 항목의 호버·키보드 포커스는 녹색 배경과 연녹색 글자로 구분한다.

### 채팅 화면과 입력창

- /owner/chat의 기본 화면은 새 대화 화면이다. 사용자 AI 대화 상단에 제목·안내 문구를 위한 별도 헤더를 추가하지 않는다. 정보이용자 AI 대변인의 클론 식별·안내 영역은 별개로 유지한다.
- 새 대화 안내와 추천 주제는 사이드바를 제외한 채팅 뷰포트의 대화 영역 중앙에 가로·세로 정렬한다. 입력창은 하단에 유지한다.
- 추천 주제 버튼은 border-radius: 999px의 캡슐 스타일을 사용한다.
- 대화는 미니멀형으로 표시한다. 내 메시지는 내용 길이에 맞는 우측 연녹색 버블(모서리 20px), AI 답변은 배경·테두리·최소 높이 없는 본문으로 표현한다. 이름은 작은 보조색으로 표시하고 정정·근거 기능은 각 본문 아래에 둔다. 대화 간격은 32px이며 긴 문자열과 줄바꿈을 지원한다.
- 채팅 입력 컨테이너는 div이다. form이나 textarea로 바꾸지 않고 input type="text"를 사용한다.
- 입력 컨테이너 div는 대화 내용과 동일하게 width: 100%, max-width: 800px로 중앙 정렬한다. 대화와 입력 영역의 좌우 패딩은 데스크톱 28px, 모바일 20px로 맞춘다.
- 입력 컨테이너는 높이 76px, 네 모서리 radius 38px로 양 끝이 반원이 되도록 한다.
- input과 버튼은 한 줄에 배치한다. input은 flex: 1, min-width: 0으로 남은 너비를 채운다.
- 오른쪽 버튼 순서는 마이크 → 전송이다. 버튼은 44×44px, radius 50%를 사용한다.
- 마이크를 누르면 대화 영역과 입력 컨테이너의 위치·크기는 유지하고 입력창 내부만 파형·경과 시간·오른쪽 닫기(×) 버튼으로 전환한다. 왼쪽 취소 버튼과 미리보기 안내 문구는 표시하지 않는다. 닫기·Escape는 기존 입력을 보존하며 예시 문장을 자동 삽입하지 않는다. 현재 실제 녹음·음성 인식은 연결되지 않은 목업이다. 타이머는 종료·컴포넌트 해제 시 정리한다.
- "음성으로도 이야기할 수 있어요" 문구는 표시하지 않는다.
- "AI가 잘못 이해할 수 있어요. 나의 발언은 언제든 정정할 수 있어요."는 입력창 아래에서 채팅 뷰포트 기준 가로 중앙 정렬한다. 사이드바 너비를 보정해 전체 브라우저 화면 중앙으로 옮기지 않는다.
- 전송 버튼과 Enter로 전송한다. 공백 메시지는 무시하고, 한글 IME 조합 중 Enter가 전송되지 않도록 한다.
- +로 연 빈 대화는 최근 대화에 넣지 않는다. 첫 메시지를 보내고 대화가 시작되는 시점에 한 번만 추가한다. 현재는 목업 응답을 사용하며, 목록은 새로고침 시 초기화되는 메모리 상태이다.

### 접근성과 검증

- 이동은 Link, 펼치기·접기·전송 같은 동작은 button type="button"을 사용한다.
- 아이콘 버튼에는 aria-label을 제공한다. 하위 메뉴에는 aria-expanded와 aria-controls를 적용하고, 키보드 포커스 표시를 제거하지 않는다.
- 스타일 리팩터링은 기존 레이아웃·색상·간격·동작을 유지하는 것이 기본이다. 관련 없는 화면까지 재설계하지 않는다.
- 변경 범위에 맞게 린트·빌드와 브라우저 확인을 수행한다. 유틸리티 전환이나 레이아웃 변경 시 데스크톱·모바일 및 팝업·메뉴·채팅 입력을 확인한다.
- 변경이 화면에 보이지 않으면 실제 적용 CSS와 실행 중인 서버를 확인한다. 확인 없이 더 강한 선택자나 !important를 반복해서 추가하지 않는다.

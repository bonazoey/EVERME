# 검증 기록

2026-11-26, Java 21 / 로컬 Docker PostgreSQL 17 + pgvector에서 검증했다. 기존 프로젝트 DB 서버에는 접속하지 않았다.

## 자동 테스트

전체 Gradle 테스트 23개가 통과했다. 이 중 실험 통합 테스트는 별도 `everme_lab_test` DB와 가짜 LLM 응답을 사용한다.

- 140개 요소·7개 영역·점수 범위·NULL/50 구별·단일 내향/외향 축.
- 생성/분석/저장의 독립성, 재저장·동시 저장 중복 반영 방지.
- 근거 ID·병합 산술 오류 차단, 임베딩 실패 시 미저장.
- 기억 INSERT의 실제 DB 제약 오류 발생 시 7개 프로필·버전·배치 상태 롤백.
- 10쌍 × 100개 배치 = 1000쌍 자동 처리, 실패한 배치를 재생성하지 않고 재개, 중단 상태.
- 소유자 범위, 새 대화·이전 sessionId 거부, CONTEXT/MEMORY/PROFILE/INSUFFICIENT 경로, 기억 조회 전 프로필 도구 차단.
- HTTP 화면·카탈로그·입력 검증과 실험 프로필 미활성화 시 컴포넌트 비등록.
- 기존 엔드포인트 계약·기존 애플리케이션 컨텍스트 테스트.

## 브라우저

Chrome headless에서 API 응답을 가짜 데이터로 대체해 버튼 단계와 클론 질문·새 대화를 확인했다. 1440px / 390px / 320px에서 가로 넘침과 JavaScript 예외가 없었다. 데스크톱 분석 화면과 320px 정보이용자 화면을 이미지로 확인했다.

기계적 디자인 검사는 서버의 `/lab/assets/lab.css` 경로를 파일시스템으로 해석하지 못해 글꼴 계층 경고를 냈다. 실제 렌더에서는 CSS가 로드되고 본문·제목의 크기가 구분되는 것을 확인했다.

## 실제 모델 연결

- gpt-6.1-sol / gpt-6.1-terra / text-embedding-3-small 접근 확인.
- 고정 가상 인물 1명과 대화 10쌍 생성.
- 실제 사용자 발언 분석 결과: 관찰 요소 34개, 기억 17개. 나머지 요소는 미확인 유지.
- LLM 병합 계산 검증 후 프로필 version 1 저장, 재저장으로 버전이 증가하지 않음 확인.
- 저장 배치를 통한 CONTEXT 답변과 실제 `searchLongTermMemory` 호출을 거친 MEMORY 답변 확인.
- PROFILE와 정보 부족 경로는 자동 통합 테스트로 검증했다. 실제 모델로 1000쌍을 실행하지는 않았다.

모델 응답의 의미적 정확성·심리측정 타당성·장기간 변화에 대한 적합성·모든 사실 날조 방지를 증명한 결과는 아니다. 실제 호출 사용량과 테스트 스크린샷은 무시되는 `backend/build/` 아래에 남긴다. 커밋·푸시는 수행하지 않았다.
# 2026-11-27 파이프라인 변경 검증

이 절은 앞의 2026-11-26 기록을 대체하는 파이프라인 검증 결과다. 이후 Spring AI 전환 결과는 다음 절을 참고한다.

- 전체 Gradle 테스트 52개 통과, 실패·건너뜀 0개. 모의 모델과 전용 PostgreSQL 테스트 DB를 사용했다.
- 한 배치에 1000쌍·100개 구간을 생성하고, 구간 순서대로 저장해 프로필 버전이 100회 증가하는 것을 검증했다.
- 생성과 분석의 실제 중첩, 작업별 동시 실행 1개, 생성 예약을 포함한 미저장 최대 20쌍을 검증했다.
- 생성·분석·저장 중 중단, 실패 후 재개, 서버 재시작 복구, 기존 single-session-v1 실행 재개를 검증했다.
- 고정 원문 ID, 중복 근거 제외, 관찰 없는 구간 완료, 동시 저장의 멱등성 및 원자적 저장을 검증했다.
- 요소별 상한·NULL·HALF_UP 반올림을 서버 계산으로 검증했다. 병합 LLM 호출은 제거됐다.
- 로컬 가짜 HTTP 서버로 재시도 대상·최대 5회 요청·Retry-After·중단·영구 오류 및 잘못된 JSON의 재시도 금지를 검증했다.
- 축소 카탈로그의 140개 코드·앵커·예시 보존과 고정 developer 입력을 검증했다.
- Playwright로 수동 대화·분석·저장과 파이프라인 진행률·수동 변경 잠금·저장 전 미리보기를 검증했다. PC 및 320px 모바일 화면을 확인했다.

실제 유료 API 호출이나 실제 모델의 1000쌍 실행은 수행하지 않았다. 실제 품질·지연·비용·캐시 적중률은 별도 소량 실험이 필요하다. LLM 호출 시간 합계는 병행 실행으로 실제 활성 경과 시간보다 클 수 있으며, 집계된 토큰은 응답에서 확인 가능한 성공한 텍스트 호출 기준이다.

## 2026-11-27 Spring AI 전환 검증

- 전체 Gradle 테스트 58개 통과, 실패·건너뜀 0개. 이전 파이프라인·클론 대화의 DB 통합 검증을 포함한다.
- 생성·분석·요약·일반 응답은 실제 Spring AI `ChatClient`와 `OpenAiChatModel`을 거쳐 로컬 가짜 Chat Completions 서버에 요청한다. strict JSON Schema, 단계별 모델·추론 강도, 샘플링 기본값 미전송, 토큰·캐시 집계, 재시도 상한을 검증했다.
- 고정 지침과 카탈로그가 첫 system 메시지에 있고 가변 원문이 다음 user 메시지에 있는 것을 검증했다. 분석 카탈로그와 근거 검증은 유지한다.
- `OpenAiEmbeddingModel`의 모델·1536차원 요청, 결과 차원·개수 검증과 빈 입력 시 호출 생략을 검증했다.
- Responses 호환 `ChatModel`에서 reasoning 항목과 function_call/function_call_output의 순서·내용이 다음 요청까지 보존되는 것을 검증했다.
- 기억 검색·프로필 조회는 `ToolCallback`을 사용하며 기존 소유자 범위·도구 순서·답변 근거 테스트가 통과했다.
- 실험 전용 모델 빈의 연결과 clone-lab 프로필 밖의 비등록을 검증했다. 기존 DB 테이블·REST 경로는 변경하지 않았다.

실제 OpenAI 호출은 수행하지 않았다. 전환 후 실제 모델의 지연·응답 품질·계정별 Chat Completions 접근 가능 여부는 이번 모의 검증의 범위 밖이다. 이전 실제 API 측정 결과를 전환 후 성능으로 간주하지 않는다.
